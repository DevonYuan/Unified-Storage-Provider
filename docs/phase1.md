# Phase 1 - Web App Skeleton

In this phase, we will build a minimal working web application with a local development setup. The app will separate concerns between a FastAPI backend and a React/Vite frontend, communicate via REST API, and use Supabase (PostgreSQL) as the database. Authentication is intentionally simplified: the sole user does not enter credentials. A single button creates a persistent local session.

> **Context:** Read `README.md` and `docs/progress.md` before coding. Testing must always be written before implementation. All tests must clean the database by themselves.

---

## Table Definitions

### `users`
| Column | Type | Notes |
|--------|------|-------|
| `id` | `bigint` | Primary key, generated by default as identity |
| `created_at` | `timestamptz` | Default `now()` |
| `updated_at` | `timestamptz` | Default `now()`, updated on change |

### Sessions / Auth
No separate table is strictly required. We will use a JWT issued by the backend after the user clicks **"Open Storage"**. The token is stored in `localStorage` on the frontend. Backend middleware validates the token and attaches the user ID to the request state.

---

## Acceptance Criteria

Phase 1 is complete when:
1. The backend serves a health-check endpoint and an authenticated `/auth/me` endpoint.
2. The frontend shows a landing page with an **"Open Storage"** button.
3. Clicking the button calls `POST /auth/session`, creates (or retrieves) the single user in the database, stores the returned access token, and navigates to a placeholder home page.
4. Clicking **"Close Storage"** removes the token from `localStorage` and redirects to the landing page.
5. Unauthenticated access to `/` redirects to the landing page.
6. Authenticated access to `/` shows a basic placeholder page with the user's session confirmed.
7. All tests pass and leave no orphaned database rows.

### 2. Write failing tests first
Per project rules, write tests before implementation.

**Backend tests (`tests/test_auth.py`):**
- `POST /auth/session` returns `200` and an access token
- `POST /auth/session` creates a user row only if none exists (idempotent)
- `GET /auth/me` with a valid token returns the current user
- `GET /auth/me` without a token returns `401`
- `GET /auth/me` with an invalid token returns `401`
- Database rows created during tests are removed in test teardown

**Frontend tests (Vitest + React Testing Library):**
- Landing page renders **"Open Storage"** button
- Clicking **"Open Storage"** calls the backend and stores the token in `localStorage`
- Authenticated view shows a welcome state
- **"Close Storage"** removes the token and redirects to the landing page

### 3. Implement the backend
- **`config.py`**: Load environment variables (`DATABASE_URL`, `JWT_SECRET`, `JWT_ALGORITHM`, `ACCESS_TOKEN_EXPIRE_MINUTES`).
- **`database.py`**: Async SQLAlchemy engine and session factory pointing at Supabase PostgreSQL.
- **`schemas/auth.py`**: Pydantic models for `SessionResponse`, `UserResponse`.
- **`services/user_service.py`**: 
  - `get_or_create_user(session, user_id)` - returns the single user row.
  - `create_access_token(user_id)` - encodes a JWT.
- **`middleware/auth.py`**: FastAPI dependency that extracts the `Authorization: Bearer <token>` header, decodes the JWT, and returns the user ID.
- **`routes/auth.py`**:
  - `POST /auth/session`: Returns a new JWT (creates user if necessary).
  - `GET /auth/me`: Returns current user info.
- **`main.py`**: Include routers and basic CORS middleware for frontend origin.

### 4. Implement the frontend
- **`src/services/api.ts`**: Axios (or fetch wrapper) configured with the backend base URL.
- **`src/services/auth.ts`**: `login()` calls `POST /auth/session` and stores the token; `logout()` clears token; `getUser()` calls `GET /auth/me`.
- **`src/components/StorageButton.tsx`**: Button that triggers `login()`.
- **`src/components/LogoutButton.tsx`**: Button that triggers `logout()`.
- **`src/pages/LandingPage.tsx`**: Shows **"Open Storage"** button when not authenticated.
- **`src/pages/HomePage.tsx`**: Protected route placeholder. Shows welcome state with user info and **"Close Storage"** button.
- **`src/App.tsx`**: Routing (`/` -> Landing or Home based on auth state).

### 5. Manual testing
- Run backend (`uvicorn app.main:app --reload`) and frontend (`npm run dev`).
- Open browser to frontend URL.
- Verify landing page shows **"Open Storage"**.
- Click the button: page should transition to home and display a user/session confirmation.
- Verify `/auth/me` returns `200` in browser dev tools Network tab.
- Click **"Close Storage"**: page should return to landing.
- Verify `/auth/me` returns `401` after logout.
- Restart backend and refresh frontend while still "logged in" (token persists) - should remain on home page.
